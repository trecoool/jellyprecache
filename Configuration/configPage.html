JellyPrecache

Image requests are snapped up to the nearest configured width (else the largest), and the "Pre-generate image sizes" scheduled task resizes every image to those widths. Unchecked types are passed through to Jellyfin untouched. Empty widths use the greyed defaults.

Also when an item gets new images. Otherwise they are generated by the nightly task, or on first view.
Keep below 90: at 90+ Jellyfin serves originals narrower than the target straight from disk.

Cache

Rebuild the whole image cache?

This will:

  1. Delete every cached image (all sizes and formats, ). Original images are not touched.
  2. Re-download missing originals from the metadata providers (TMDb etc.) for any item whose image file is gone.
  3. Regenerate every configured size and format for the whole library.

Until it finishes, thumbnails load slowly and the media disks may wake up.
